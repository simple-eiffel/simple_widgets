Overview

simple_widgets is the missing middle layer of the Simple Eiffel GUI story. The classic chain was WEL (raw Win32) → Vision2 (portable widgets) → your application. The simple chain is simple_cairo (the substrate) → simple_widgets (the vocabulary) → your application (the intent). Before this library existed, a production face meant two thousand lines of boilerplate above the canvas; that boilerplate is now a toolkit.

Every pixel is drawn by the toolkit itself onto one cairo surface in one plain Win32 window: buttons, text boxes with spell-checking, menus, dialogs, toasts, tabs, virtualized lists, splitters, a complete file dialog. There are no child HWNDs, no common controls, no native anything - which is why every control looks identical, themes swap live, and the whole face is testable headless.

58 pages cover every class shipped across Waves 1-2, Wave 3's first batch, and one planned control kept visible on purpose; the catalog (specs/S02) plans coverage of the full desktop-and-web widget union across six waves. Part of the Simple Eiffel ecosystem.

Architecture: five layers (spec S01)

LayerWho lives thereCharacter
COMPOSITIONYour application Pure intent - what exists and what happens
COMPONENTSW_FILE_DIALOG, cards, groups Widgets assembled into meaningful units
WIDGETSW_BUTTON … SW_LIST Controls: state, contracts, input handlers
PAINTERSW_PAINTER, SW_THEME The drawing vocabulary and the visual truth
SURFACESW_WINDOW + Clib runtime Win32 window, cairo surface, event pump

Higher layers are simpler and faster to use; lower layers are more expressive and more verbose. Applications normally live at the top two; the escape hatches down are deliberate and rarely needed.

The rules the toolkit lives by

#Rule
R1One language: Eiffel over inline C externals; no separate C toolchain steps.
R2Painter monopoly: only SW_PAINTER touches CAIRO_CONTEXT.
R3Contracts everywhere: state machines carry invariants; protocols carry pre/postconditions.
R4Theme is truth: no literal colours or sizes in widgets - tokens only.
R5Agents wire behaviour: on_change/on_select/actions, never inheritance-to-configure.
R6Immediate feedback: every interaction shows its effect now (toast, status, preview).
R7Nothing native: menus, dialogs, toasts, file dialogs - all drawn. OS services without pixels (clipboard, keys, spelling) are welcome.
R8Unicode first: STRING_32 through every API; surrogate pairs handled at the borders.

Quick Start

Installation

  1. Add to your ECF: 
    <library name="simple_widgets" location="$SIMPLE_EIFFEL/simple_widgets/simple_widgets.ecf"/>
  2. Ship cairo.dll beside your executable (every finalize wipes F_code - copy it back).

A whole application

local
    window: SW_WINDOW
    theme: SW_THEME
    root: SW_COLUMN
do
    create theme.make_dark
    create window.make ("hello", 100, 100, 900, 700, theme)
    create root.make
    root := root.with_padding (16.0).with_gap (12.0)
    root.put (create {SW_LABEL}.make_body ("Every pixel here is the toolkit's own."))
    root.put (create {SW_BUTTON}.make_primary ("Go", agent on_go))
    window.set_root (root)
    window.run
end

The living cookbook is demo/sw_demo.e - the showroom exercising every control; build it with the commands under Testing.

Testing: the contract assault

The library ships a test target that drives the model layer headless - including drawing, via a painter over an offscreen cairo surface - with every assertion live (F_code with contracts kept). 74 tests across ten assault sets; the suite caught three real defects on its first day (a truncation alias in list row math, a clipboard race against history managers, and an ECF namespace clash). 

# build the demo showroom
/d/prod/ec.sh test -config simple_widgets.ecf -target sw_demo

# build and run the contract assault
/d/prod/ec.sh test -config simple_widgets.ecf -target simple_widgets_tests
cp $SIMPLE_EIFFEL/simple_cairo/cairo.dll EIFGENs/simple_widgets_tests/F_code/
./EIFGENs/simple_widgets_tests/F_code/simple_widgets.exe

Platform notes

  • Windows only today: the SURFACE layer is Win32; spelling is ISpellChecker (Windows 8+). Everything above the surface is portable by design.
  • Per-monitor DPI aware; all coordinates are physical pixels.
  • Dark and light palettes ship; dark is the house default.
