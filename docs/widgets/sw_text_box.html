Description

SW_TEXT_BOX owns what an edit is: a per-character layout cache (measure-then-place greedy word wrap), a caret, a primary selection anchored at sel_anchor, and disjoint extra ranges - Notepad++-class multi-selection reached through invert_selection. Copying disjoint pieces joins them with newlines.

The keyboard map: arrows/Home/End/Up/Down move the caret (Shift extends), Backspace/Delete edit, Ctrl+A / C / X / V select and use the clipboard, Escape collapses the selection. Mouse: click places the caret, Shift+Click extends, drag sweeps, double-click selects a word, triple-click selects everything. Right-click produces the standard editor menu - and when the click lands on a misspelled word, the spelling suggestions lead the menu and one click applies the fix.

Spelling rides Windows' ISpellChecker through SW_SPELLER: misspelled ranges get danger underlines, refreshed lazily on change. Windows-only by nature; elsewhere the box simply never underlines.

Password mode (make_password): bullets are fed to both the renderer and the layout measurer, so caret math always matches the pixels. Three denials protect the secret: no clipboard copy/cut-out, no spellcheck (the OS never sees the text), and the context menu mutes Cut/Copy. A reveal eye at the right edge (toggle_reveal) shows the text - a view change only; the denials hold while revealed.

Boxes are also pick-and-drop holes: any string pebble dropped on a writable box inserts at the caret (accepts_pebble / receive_pebble).

Source: src/sw_text_box.e · since Wave 1 (2026-08-21). Live in the showroom: demo/sw_demo.e.

Creation modes and wiring

-- multi-line, wrapping, spell-checked
create notes.make (class="string">"The quick brown fox jumps over the lazy dog.")
notes.set_on_change (agent on_notes_changed)

-- one line: Enter is swallowed, pasted newlines flatten to spaces
create name_box.make_single_line (class="string">"untitled.txt")

-- masked: bullets, no copy, no spellcheck, reveal eye at the right
create pw.make_password (class="string">"hunter2")

-- programmatic selection surgery
notes.select_all
notes.invert_selection      -- disjoint complement
print (notes.selected_text) -- pieces joined with newlines

The set_text law

-- set_text re-establishes EVERY invariant of the new text:
-- caret clamps, the anchor collapses, stale extra ranges die,
-- spelling re-queues. Found by contract, sealed by regression test.
notes.set_text (class="string">"shorter")

Known limits

  • No undo/redo yet - the most-missed feature; it is first in line (see Future).
  • Single-line boxes do not scroll horizontally; text beyond the width clips until the box grows.
  • No IME composition window for CJK input; code points arrive via WM_CHAR only (surrogate pairs are handled - see R8 - but composition UX is absent).
  • Word wrap is greedy per word; no hyphenation or break-opportunity analysis.
  • Spelling and suggestions are Windows-only (ISpellChecker).

Bugs & gotchas

  • Selection is drawn only while the box has focus - Select All from a context menu works because right-click transfers focus first. If you script the box headless, remember there is no window to grant focus.
  • Masked boxes refuse clipboard copy even while revealed - by design (clipboard managers are the threat), so do not build a 'copy password' button on top of one.
  • set_text collapses all selection state on purpose; capture selected_text first if you need it.
  • An astral character (emoji) is ONE code point in text but TWO UTF-16 units in transit; the box and clipboard pair surrogates for you - never index text by UTF-16 unit counts.

Extension plans & possibilities

  • Undo/redo stack (command-pattern edits are a natural fit for the engine).
  • Find/replace bar riding the same range machinery as multi-select.
  • Horizontal scroll + ellipsis policies for single-line mode.
  • Push-to-talk dictation (whisper.cpp, CPU-only) feeding receive_pebble-style insertion - queued from the AI-assist survey (R03).
  • Syntax-colouring hook: a per-range style agent, same shape as spell ranges.
