Windows ISpellChecker as a service: misspelled ranges in, suggestions out.

Description

SW_SPELLER wraps the Windows 8+ ISpellChecker COM API: misspellings (text) returns [lo, hi] ranges of flagged words; suggestions (word) returns replacement candidates. SW_TEXT_BOX uses both - danger underlines from the ranges, suggestion items leading the context menu.

Windows-only by nature. On systems without the COM service the queries return empty lists and text boxes simply never underline - features degrade to absence, never to failure.

Source: src/sw_speller.e · since Wave 1 (2026-08-21). Live in the showroom: demo/sw_demo.e.

Direct use

local
    sp: SW_SPELLER
do
    create sp
    across sp.misspellings (class="string">"this sentnce has a probelm") as r loop
        print (class="string">"flagged: " + r.lo.out + class="string">".." + r.hi.out + class="string">"%N")
    end
    across sp.suggestions (class="string">"sentnce") as s loop
        print (s + class="string">"%N")
    end
end

Known limits

  • Windows-only (documented library-wide); empty results elsewhere.
  • Dictionary language follows the user's Windows language settings - not selectable per call yet.
  • Word-level checking only: no grammar (evaluated and deliberately deferred - the CPU-model survey R03 has the notes).

Bugs & gotchas

  • Masked text boxes never consult the speller - secrets are not sent to OS services. If you build custom secret fields, honor the same rule.
  • Results vary by machine (user dictionaries, languages) - test suites should smoke-test the plumbing, not assert specific words.

Extension plans & possibilities

  • Per-language checker selection; user-dictionary add ('Add to dictionary' menu item).
  • Grammar layer if a CPU-honest engine earns its keep (Harper was surveyed; deferred).
  • Push-to-talk dictation is a sibling service in waiting (whisper.cpp, R03).
