Description

SW_WIDGET is the deferred root of every control. It owns bounds (x, y, width, height in surface pixels, set by containers), layout hints (grow - the flex weight; min/max anchors applied through clamped_width/clamped_height), and interaction state the window maintains: is_enabled, is_hovered, is_pressed, is_focused.

Input arrives through redefinable handlers: handle_click, handle_double_click, handle_triple_click (BOOLEAN - return True to consume; unconsumed clicks bubble up the parent chain), handle_drag, handle_char, handle_key, handle_wheel.

Three declarative protocols keep widgets out of the window's business: pending menus - a widget sets pending_menu in its click handler and the window presents it at the widget's foot; context menus - the window asks context_menu (x, y) on right-click; and pick-and-drop - pebble / pebble_at (x, y) offer a value, accepts_pebble is the target's contract, receive_pebble completes the transaction (its precondition is that the pebble was welcome).

Hover feedback is on by default and individually silenceable (set_hover_signal / hover_silenced); widgets that need the pointer's position while hovered opt in with wants_hover_point.

Source: src/sw_widget.e · since Wave 1 (2026-08-21). Live in the showroom: demo/sw_demo.e.

A minimal custom widget

class MY_BADGE

inherit
    SW_WIDGET

create
    make

feature {NONE} -- Initialization

    make
        do
        end

feature -- Layout

    preferred_height (a_p: SW_PAINTER; a_width: REAL_64): REAL_64
        do
            Result := 24.0
        end

feature -- Drawing

    draw (a_p: SW_PAINTER)
        do
            a_p.set_color (a_p.theme.wash_accent)
            a_p.rrect_fill (x, y, width, height, a_p.theme.radius)
        end

end

The fluent layout hints

-- flex weight, min and max - chainable at construction
buttons.put ((create {SW_BUTTON}.make (class="string">"Grows", Void)).growing)
row.put (box.with_min_size (100.0, 40.0).with_max_size (300.0, 40.0))
lbl := lbl.with_tooltip (class="string">"shows after a short hover dwell")

Known limits

  • No keyboard focus traversal yet - Tab does not move focus between widgets; focus follows clicks.
  • State flags are window-maintained; driving a widget headless (as the test suite does) means calling handlers directly - hover/pressed stay False unless you set them.
  • Only rectangular hit-testing (contains / widget_at).

Bugs & gotchas

  • The fluent for flex-grow is growing, not expanded - expanded, like frozen, old and variant, is an Eiffel keyword. Four names died learning this.
  • Disabled widgets are inert AND transparent: clicks pass through to the parent chain.
  • handle_click returning False means 'not mine' - the parent gets a turn. Consume deliberately.
  • Attributes like caret on descendants are client-readable but never client-assignable (Eiffel semantics); drive state through commands.

Extension plans & possibilities

  • Tab-order focus traversal with a visible focus ring policy.
  • dev_note metadata for the SW_INSPECTOR overlay (provenance, intent, wiring).
  • Accessibility bridge (UIA text patterns) - a research item; it must not violate R7.
  • Animation hooks (hover/press transitions driven from the tick).
