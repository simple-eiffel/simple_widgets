Description

SW_WINDOW is the only class in the toolkit that touches the operating system's windowing. It creates a plain Win32 window, allocates an offscreen cairo surface for the whole client area, pumps events, routes input to the widget tree, and blits the finished frame. There are no child HWNDs anywhere: every control, menu, dialog and toast is painted onto this one surface (rule R7 - nothing native).

Input dispatch runs in phases: an open dialog owns everything; otherwise an open popup (menu) owns the pointer; otherwise a sheet (modal widget layer) becomes the input root; otherwise a pick in flight handles drops; otherwise input flows to the widget tree. Two events are exempt from phasing - the heartbeat: tick (toast aging, frame-echo flush) and resize (surface reallocation) are handled globally before any phase, so an open menu can never freeze the window's clock.

The window also owns cross-widget services: keyboard focus, hover tracking with tooltips, toasts (toast (text, kind)), drawn modal dialogs (show_dialog), modal sheets (show_sheet / close_sheet), pick-and-drop trajectory, the pending-menu handshake, and live theme swap (set_theme).

Coordinates are physical pixels throughout - the window is per-monitor DPI aware, and the offscreen surface maps 1:1 to what you see.

Source: src/sw_window.e · since Wave 1 (2026-08-21). Live in the showroom: demo/sw_demo.e.

A complete application

local
    window: SW_WINDOW
    theme: SW_THEME
    root: SW_COLUMN
do
    create theme.make_dark
    create window.make (class="string">"my app", 100, 100, 900, 700, theme)
    create root.make
    root := root.with_padding (16.0).with_gap (12.0)
    root.put (create {SW_LABEL}.make (class="string">"Hello", {SW_PAINTER}.Role_ui, 20.0, True))
    root.put (create {SW_BUTTON}.make_primary (class="string">"Go", agent on_go))
    window.set_root (root)
    window.run   -- blocks until the window closes
end

Toasts, dialogs and sheets

-- transient feedback (kinds: 1 info, 2 success, 3 warning, 4 danger)
window.toast (class="string">"Saved", 2)

-- a drawn modal alert
create d.make ({SW_DIALOG}.Kind_danger, class="string">"Delete?", class="string">"This cannot be undone.")
d.add_button (class="string">"Cancel", False, Void)
d.add_button (class="string">"Delete", True, agent do_delete)
window.show_dialog (d)

-- ANY widget tree as a modal sheet (this is how SW_FILE_DIALOG appears)
window.show_sheet (my_form, 560.0)
-- later: window.close_sheet

Accelerators and mnemonics (0.6.0)

Until 0.6.0 a key reached exactly one place: the FOCUSED widget. An application that wanted Ctrl+N to mean New wherever the caret happened to be had nowhere to say so.

window.register_accelerator (78, True, False, False, agent new_document)
        -- Ctrl+N, anywhere in this window, whoever holds focus
window.register_accelerator (83, True, False, True,  agent save_as)
        -- Ctrl+Shift+S is a DIFFERENT key: the modifiers must match exactly

accelerators, accelerator_for (0 = unclaimed), fire_accelerator and clear_accelerators are the whole model. A modifier is REQUIRED - an unmodified accelerator would take the letter out of every text box in the window. An UNCLAIMED Ctrl+A / C / V / X / Z / Y still reaches the focused SW_TEXT_BOX exactly as it always did. No existing signature changed: SW_WIDGET.handle_key (a_vk, a_shift) is untouched.

Both key doors are tried. simple_shell's WM_KEYDOWN filter forwards only the stepping keys (arrows, Home/End, Page keys, Delete, OEM plus/minus) as event 4, so a letter never arrives that way; Ctrl+C arrives as event 3, the WM_CHAR control code 3. The table is consulted on both, and a hit on the key-down door swallows the WM_CHAR that trails it.

Menu mnemonics. window.set_menu_bar (bar) gives a bar the Alt key; activate_mnemonic ('F') opens the pad that declares &File, dropped under the pad itself (SW_MENU_BAR.pad_bounds - the same geometry a click hit-tests with). open_popup is the read-only view of what is up. While a menu is open a BARE letter picks the item that underlines it.

THE ALT GAP, NAMED. Alt STATE is exposed (SW_KEYS.alt_down), so an Alt accelerator matches. Alt+letter DELIVERY is not: simple_shell answers WM_SYSKEYDOWN only for the OEM plus/minus pair and lets every other syskey fall through to DefWindowProc. Until simple_shell forwards WM_SYSKEYDOWN/WM_SYSCHAR for letters, Alt+F reaches the system menu and not this window. activate_mnemonic is implemented, contracted and tested, and a host can drive it from a Ctrl accelerator or a click today. Ctrl accelerators work end to end NOW.

Known limits

  • One window per application for now - no secondary or child windows yet.
  • The frame echo (set_frame_echo) writes PNG lazily on the tick, not on every render - it is a debug instrument, not a video feed.
  • Cursor shaping SHIPPED 2026-08-23: widgets declare cursor_kind (I-beam over text, resize arrows over dividers), applied on hover through simple_shell's WM_SETCURSOR path.
  • Redraws repaint the full frame; very large windows pay for it on resize drags (felt as slight grow-lag).

Bugs & gotchas

  • cairo.dll must sit beside the executable. Every finalize wipes F_code, deleting the DLL; the exe then dies at load looking exactly like a code crash. Copy it back after every build.
  • run blocks. Everything after it executes only when the window closes.
  • Window geometry is physical pixels. If a DPI-unaware shell moves the window (MoveWindow from PowerShell), the OS scales the coordinates - at 150% they land 1.5× away from where you aimed.
  • Popups close on the next button-down anywhere; if a menu 'never appeared', something (or someone) clicked between open and look.

Extension plans & possibilities

  • Multi-window support (owner/owned, drawn dialogs across windows).
  • Cursor API (I-beam over text, resize arrows over splitters).
  • Dirty-rectangle rendering and batched text runs to erase resize lag.
  • Dev-mode inspector overlay (SW_INSPECTOR, S02): reflection-driven widget reveals behind an ECF debug ("dev_mode") compile-time gate.
  • Per-window text scale (grow/shrink all fonts) via a theme scale factor.
