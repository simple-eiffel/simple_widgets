Description

SW_COLUMN stacks children top to bottom with a gap, inside optional padding. Heights come from each child's preferred_height (given the column's width) clamped by its anchors; leftover height is distributed to growing children. Every window's root is a column; cards, groups and the file dialog are columns wearing clothes.

The pinned footer idiom: [content…, SW_SPACER, SW_STATUS_BAR] - the spacer absorbs all slack, so the bar hugs the window's bottom edge at any size. Layout discipline replaces a docking API.

Source: src/sw_column.e · since Wave 1 (2026-08-21). Live in the showroom: demo/sw_demo.e.

A root with a pinned footer

create root.make
root := root.with_padding (16.0).with_gap (14.0)
root.put (menubar)
root.put (toolbar)
root.put (content_card)
root.put (create {SW_SPACER}.make)   -- absorbs the slack
root.put (statusbar)                 -- pinned to the bottom edge
window.set_root (root)

Known limits

  • No horizontal scrolling of overflow; a column taller than its slot clips (put it in an SW_SCROLL_AREA).
  • Grow distribution shares positive leftover only; when content exceeds the window, excess simply runs past the bottom.

Bugs & gotchas

  • Padding lives on the column, gap between children - mixing per-child margins into widgets fights the engine; spacing belongs to containers.

Extension plans & possibilities

  • Scroll-aware columns (auto-adopt a scroll area when overflowing).
  • Named layout regions (header/content/footer sugar over the spacer idiom).
