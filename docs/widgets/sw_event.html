Description

Larry's design note became the layer: every EV control carries agent COLLECTIONS per event, and those collections - permanent subscribers beside one-shot kamikazes - ARE the GUI's state machine. SW_EVENT is that mechanism, read from the installed EiffelStudio 25.02 source (base/ise/event/action_sequence.e) at his direction and kept faithful where the architecture earns it: one ordered roll (kamikazes fire in subscription order beside permanents, and are off the roll before their bodies run), an abort protocol (any action can stop the remainder of its round; a stack keeps nested rounds honest), and the state trio - Normal calls through, pause buffers event data until resume replays the backlog, block drops calls cold, flush discards the buffer. Rounds work a snapshot, so subscribing or pruning mid-fire never corrupts the round.

Vocabulary is double-salted for both hands: Vision2's call / extend / extend_kamikaze / prune alias the native fire / subscribe / kamikaze / unsubscribe.

Adoption, first ring. The widget spine exposes four lazily-created state queues - on_focus_change, on_hover_change, on_press_change, on_enabled_change - fired by the setters on CHANGE only (an unobserved widget pays a single Void test). The sensitivity pass speaks through the same queue: an enabled_when verdict that flips a widget fires on_enabled_change like any other cause. SW_BUTTON adds click_actions beside its legacy single agent. And the CAIRO pipeline has its own bells (Larry: cairo-based event queues): the window's before_render_actions and after_render_actions - the latter delivering last_render_ms, so perf instruments subscribe instead of being wired in.

The idea is deliberately bigger than the GUI: any class wanting an on_[event] surface can hold SW_EVENT instances - the state-machine mechanism with no widget in sight. If non-GUI simple_* libraries reach for it, it graduates into its own library (simple_events).

Source: src/sw_event.e · since Wave 3 coda (2026-08-22). Live in the showroom: demo/sw_demo.e.

Permanents, kamikazes, and the render bell

-- a permanent observer and a one-shot beside it
save_button.click_actions.subscribe (agent on_save)
save_button.click_actions.kamikaze (agent on_first_save_ever)

-- the spine's state machine, observable
name_box.on_focus_change.subscribe (agent on_name_focus)

-- batch a storm: pause, mutate, resume replays the backlog
list.on_enabled_change.pause
across widgets as w loop w.refresh_enabling end
list.on_enabled_change.resume

-- the cairo bell: perf instruments subscribe, not wire
window.after_render_actions.subscribe (agent on_frame_cost)

on_frame_cost (a_ms: INTEGER)
    do
        if a_ms > 32 then statusbar.set_left (class="string">"slow frame: " + a_ms.out + class="string">"ms") end
    end

Known limits

  • unsubscribe/prune is identity-based: pass the SAME agent object you subscribed (keep it in an attribute if you plan to leave).
  • Spine queues fire on CHANGE only - re-asserting the same state is silence by design.
  • Controls beyond SW_BUTTON still carry single-agent slots; the queue sweep is control-by-control (the single setters stay - they are the simple hand).

Bugs & gotchas

  • A kamikaze subscribed DURING a round waits for the next event (rounds work a snapshot).
  • abort stops the CURRENT round only - it prunes nobody.
  • resume replays buffered calls with their ORIGINAL event data, in order - flush first if the backlog is stale.

Extension plans & possibilities

  • Queue sweep across controls (on_change, on_select, on_drop as SW_EVENT beside the legacy single agents).
  • not_empty/empty meta-actions (ACTION_SEQUENCE has them) if lazy backends ever need to know they are observed.
  • Graduation to simple_events when a non-GUI library subscribes.
