Description

SW_LIST renders only the visible band: the host supplies row_count and a row_renderer agent (painter, index, x, y, width, height), and rows outside the viewport are never laid out, never drawn, never hit-tested. Uniform row height, wheel + thumb scrolling, hover band under the pointer.

Selection is a single row painted as an accent wash beneath the renderer's own drawing: click selects, select_row commands, on_select reports. Activation is the double-click (on_activate) - the file dialog navigates folders with it. Per-row pebbles: set_row_pebble supplies a value per index, surfaced through the position-aware pebble_at protocol, so middle-click picks work row by row even though the widget is one object.

This class carries two of the assault suite's trophies: scroll_to_row called before layout used to die on its own postcondition (it now degrades honestly pre-layout), and row_at aliased points above the list to row 1 because truncation rounds toward zero (now guarded, with a postcondition naming the rule).

Source: src/sw_list.e · since Wave 1 (2026-08-21); selection, activation and per-row pebbles Wave 2. Live in the showroom: demo/sw_demo.e.

Ten thousand rows, one agent

create lst.make (170.0)
lst.set_row_count (10000)
lst.set_row_renderer (agent render_row)
lst.set_on_select (agent on_row_selected)
lst.set_on_activate (agent on_row_opened)
lst.set_row_pebble (agent pebble_for_row)

render_row (a_p: SW_PAINTER; a_i: INTEGER; a_x, a_y, a_w, a_h: REAL_64)
    do
        a_p.font ({SW_PAINTER}.Role_mono, 13.0, False)
        a_p.set_color (a_p.theme.ink)
        a_p.text (a_x + 8.0, a_y + a_h - 9.0, class="string">"item " + a_i.out)
    end

Known limits

  • Uniform row height (variable heights are a data-grid concern, Wave 3).
  • Single selection (multi-select with ranges is queued).
  • No keyboard navigation of the selection yet (arrows/PgUp/PgDn).
  • No columns, headers or sorting - that is SW_DATA_GRID's charter.

Bugs & gotchas

  • The renderer is called with the row's rectangle - draw relative to the given x/y, never to the list's own origin, or scrolling will smear your rows.
  • scroll_to_row before the first layout positions by arithmetic and only promises visibility once laid out - the postcondition spells it out.
  • Renderer agents that allocate per row (fonts are fine, objects are not) will be felt at wheel speed; keep the hot path allocation-free.

Extension plans & possibilities

  • Multi-select (extending the text box's disjoint-range vocabulary to rows).
  • Keyboard selection movement with scroll-into-view.
  • Variable row heights via a measure agent; sticky headers.
  • SW_DATA_GRID and SW_TREE build on this engine in Wave 3.
