Description

SW_DATA_GRID is generic over the row type: your records go in as they are (set_rows / add_row), and SW_GRID_COLUMN [G] objects give each column its meaning - a title, a width, a value agent rendering a row to text, and an optional key agent returning a COMPARABLE so numbers sort as numbers (9 < 30 < 100, where text ordering would lie).

Clicking a header sorts ascending; again, descending; a third time clears to model order - with a drawn direction triangle. Dragging a header divider resizes the column (clamped at a minimum by the column's own invariant; the divider wears a hover affordance). set_filter takes a host predicate over G - wire it from any text box for find-as-you-type. The view (filter then sort) is a mapping onto model indices; only the visible band ever draws (the SW_LIST virtualization idiom), under a frozen header, with zebra striping and both-axis wheel scrolling.

Selection follows the row OBJECT, not its position: re-sorting keeps your record selected at its new place, and a filter that excludes it clears the selection honestly. on_select and on_activate (double-click) report MODEL indices; selected_object hands back the G itself.

Read-only by design in v1 - editing composes outside (activation opens your editor), the same domain/presentation split SW_SHEET enforces. In the three-tier doctrine this is tier two: SHEET (the grid organ) → DATA_GRID (columns first-class) → SPREADSHEET (Wave 5 composite).

Source: src/sw_data_grid.e · since Wave 3 crown (2026-08-22). Live in the showroom: demo/sw_demo.e.

A typed grid over tuples

fleet: SW_DATA_GRID [TUPLE [name: STRING_32; wave: INTEGER; category: STRING_32]]

create fleet.make (240.0)
fleet.add_column (create {SW_GRID_COLUMN [TUPLE [name: STRING_32; wave: INTEGER; category: STRING_32]]}.make (class="string">"Widget", 190.0, agent grid_name))
fleet.add_column ((create {SW_GRID_COLUMN [TUPLE [name: STRING_32; wave: INTEGER; category: STRING_32]]}.make (class="string">"Wave", 80.0, agent wave_text)).with_key (agent wave_key))
fleet.add_row ([{STRING_32} class="string">"SW_BUTTON", 1, {STRING_32} class="string">"input"])
fleet.set_on_select (agent on_row_selected)
fleet.set_filter (agent row_passes)   -- any predicate over the row type

Known limits

  • Single-row selection (multi-select ranges queued).
  • Uniform row height; no cell renderers yet (text via the value agent only).
  • Insertion sort on the view: right for human-scale row counts; thousands-of-rows sorting is an S04 item (the DRAW is already virtualized for thousands).
  • No in-place editing (by design in v1 - activation composes your editor).
  • No horizontal scrollbar drawn yet (Shift+wheel scrolls X).

Bugs & gotchas

  • Give numeric columns a key agent or they sort as text - the assault suite pins the difference with 9/30/100.
  • on_select reports MODEL indices - stable across sort and filter; do not confuse them with view positions.
  • The filter predicate closes over your state (a text box, say): re-call set_filter after that state changes - the grid cannot see through your closure.

Extension plans & possibilities

  • Multi-select with range vocabulary; cell renderer agents (chips, bars in cells).
  • O(n log n) sort for big row counts; column show/hide and reorder by drag.
  • In-place typed editors per column (tier-three groundwork).
  • Tree-table descendant (Wave 5) sharing this engine.
