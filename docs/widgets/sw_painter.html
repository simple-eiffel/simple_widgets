Description

SW_PAINTER enforces rule R2: widgets never see CAIRO_CONTEXT; they speak painter. The vocabulary: set_color (rgb) / set_color_alpha (rgb, a), font (role, size, bold) over the theme's three families, text (x, y, s) and advance (s) for layout-true measurement, fill_rect, rrect_fill / rrect_stroke, line / hline / vline, circle_stroke / circle_fill, push_clip / pop_clip, and draw_image (surface, x, y, w, h) for scaled PNG blits.

The circle primitives exist because of a bug users can see: cairo's arc appends to the current path, drawing a straight connector line from wherever the pen last was to the arc's start. Radio buttons wore dashes through their circles until the circle calls learned to reset the path first. The hygiene lives here so no widget can reintroduce it.

context remains reachable as a deliberate escape hatch for the lowest layer, but every use outside SW_PAINTER is a design smell - and the arc story is the reason why.

Source: src/sw_painter.e · since Wave 1 (2026-08-21). Live in the showroom: demo/sw_demo.e.

A widget's draw, in painter vocabulary

draw (a_p: SW_PAINTER)
    local
        t: SW_THEME
    do
        t := a_p.theme
        a_p.set_color (t.surface)
        a_p.rrect_fill (x, y, width, height, t.radius)
        a_p.set_color (t.outline)
        a_p.rrect_stroke (x + 0.5, y + 0.5, width - 1.0, height - 1.0, t.radius)
        a_p.font ({SW_PAINTER}.Role_ui, t.size_label, False)
        a_p.set_color (t.ink)
        a_p.text (x + 10.0, y + height - 11.0, class="string">"hello")
    end

Measuring before placing

a_p.font ({SW_PAINTER}.Role_ui, t.size_label, False)
w := a_p.advance (label) + 24.0   -- advance, not ink width:
                                  -- trailing spaces count, layout stays true

Shaped text (simple_shaping)

The toy path above cannot do bidi, shaping, font fallback or colour emoji. When the window has been given a shaping kit - one call, window.enable_shaped_text - the painter can paint a finished SHAPED_LAYOUT instead.

if a_p.has_shaping and then attached a_p.shaping as al_kit then
    l_layout := al_kit.layout_for (my_text, inner_width_px, pixel_size)
    a_p.draw_shaped_layout (l_layout, l_x, l_y)   -- (l_x, l_y) is a TOP-LEFT
end
  • shaping: detachable SW_SHAPING - the window's kit, or Void. Void is the default and it is not a degraded state: a widget that has not been taught shaped text keeps the toy path, unchanged.
  • has_shaping, set_shaping (a_kit) - SW_WINDOW re-attaches the kit after every painter rebuild.
  • draw_shaped_layout (a_layout, a_x, a_y) - (a_x, a_y) is a TOP-LEFT, not a baseline, unlike text. The layout already knows each line's ascent, so a caller never computes one.
  • is_resize_storm / set_resize_storm - SW_WINDOW publishes its own busy_ticks debounce here, and a shaped widget keeps the layout it has while the frame is being dragged (R10).

Sizing comes from layout.total_height, always - never a line count times a constant, because a line carrying an emoji box is taller than one that does not.

Known limits

  • Cairo toy text API: one face per call, no shaping, no bidi, no glyph fallback - a code point missing from the face renders as .notdef. Cured, opt-in, by draw_shaped_layout - see above; the toy path remains the default and the fallback.
  • No gradients, dashes or transforms in the public vocabulary yet (the escape hatch can, but that trades away R2).
  • draw_image scales the whole source; no sub-rect (sprite) blits yet.

Bugs & gotchas

  • The shaping bridge sets an explicit font antialias mode (subpixel) before it draws a glyph, and it must: without one, cairo's win32 backend renders same-pixel-size glyphs at about 1/32 scale and reports no error at all. Nothing in this painter sets a font antialias mode, so there is no conflict - but if you ever add one, read SHAPING_CAIRO_BRIDGE's class note first.
  • Never call context.arc directly - the connector-line bug. Use circle_stroke/circle_fill; they reset the path first.
  • Use advance for layout, never ink extents - ink excludes trailing whitespace and your caret math will drift.
  • set_line_width is stateful: set it back (the fleet convention is width 1.0 at rest) or the next widget strokes fat.
  • Half-pixel offsets (x + 0.5) keep 1px strokes crisp; whole-pixel strokes blur across two device pixels.

Extension plans & possibilities

  • Dirty-rect support and batched same-style text runs (the resize-lag cure).
  • Gradient and shadow tokens for depth, kept behind theme control.
  • Sub-rectangle image blits and nine-slice scaling for skinnable surfaces.
  • A recording painter for golden-frame regression tests.

The drawn-glyph set (2026-08-23)

glyph (kind, cx, cy, size) draws any of 25 kinds in the current colour, centred in a box - pure primitives, so every face ships on every machine (R7: no font-glyph gambling). The assault proves each kind leaves ink at the pixel, every run.

Glyph_plus · minus · close · check · chevron_right/down/left/up · search · gear · trash · pencil · folder · document · refresh · play · pause · stop · dots · menu · info · warning · tray · offline · error

Adopters so far: SW_BUTTON (with_glyph), SW_TOOLBAR (add_icon_item), SW_SEGMENTED (with_icon_segment), SW_EMPTY_STATE (set_glyph_kind).

Same date, one more primitive: push_circle_clip (cx, cy, r) - drawing confined to a disc until pop_clip, nesting like the rectangular clip. First consumer: photo avatars.
