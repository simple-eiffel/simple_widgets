Description

SW_MENU_BAR lays menu titles across a strip; clicking a title builds its menu by calling the registered builder agent (FUNCTION [SW_MENU]) and offers it through the pending-menu handshake. Because the builder runs at open time, item enablement is always current - the same freshness law as context menus, made structural.

Source: src/sw_menu_bar.e · since Wave 2 (2026-08-22). Live in the showroom: demo/sw_demo.e.

Three menus, three builders

create menubar.make
menubar.add_menu (class="string">"File", agent file_menu)
menubar.add_menu (class="string">"Widgets", agent widgets_menu)
menubar.add_menu (class="string">"Help", agent help_menu)
root.put (menubar)

file_menu: SW_MENU
    do
        create Result.make
        Result.add_item (class="string">"Open...", class="string">"", True, agent on_open_file)
        Result.add_item (class="string">"Save", class="string">"Ctrl+S", is_dirty, agent on_save)
        Result.add_separator
        Result.add_item (class="string">"Quit (decorative)", class="string">"", False, Void)
    end

Known limits

  • No keyboard menu access (Alt+F mnemonics) yet.
  • No overflow handling for very many titles.

Bugs & gotchas

  • Do not cache SW_MENU objects and hand the same one back from a builder - the freshness law is the point; build in the function, every time.

Extension plans & possibilities

  • Alt-key mnemonics and arrow navigation between open menus.
  • Right-aligned title zone (Help pinned right, platform-style).
