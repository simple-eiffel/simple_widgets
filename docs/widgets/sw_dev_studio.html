Description

Born from four questions Larry asked of a first mesh screenshot (what happens on node clicks? on periphery expansion? where does reflection data live? can controls be live-edited?) - the answers turned out to describe one instrument. SW_MESH graphs the widget tree as live physics: all-pairs charge repulsion, springs on parent/child edges, centre gravity, one relax step per heartbeat - the EiffelStudio Diagram Tool's family. The harvest is depth-limited (a full face is hundreds of nodes; the skeleton reads at three) and the cut line shows as plus-badged FRONTIER nodes that expand in place when clicked. The origin wears the crown: accent-filled, larger, double-ringed.

The colour grammar answers 'what would guide node colours?' with the toolkit's own semantics: fill encodes KIND (containers quiet surface, interactive controls accent-washed, passive leaves barely-there), ring encodes STATE (accent selected, ink hovered, warning pinned, danger disabled). A 'names' chip - and a context-menu item - toggles every node's class name painted beside it. Right-clicking a node offers Reveal in pane / Expand children / Release pin.

SW_DEV_STUDIO is the splitter that marries the mesh to a living pane. Clicking a node rebuilds the pane with the FULL reflected dossier (make_full, every field, in a growing scroll area); text-bearing subjects add the live-edit rig - an edit box preloaded from the subject and an 'Apply set_text' button that drives the subject's PUBLIC setter with every contract armed. A public tooling surface (pane_line_count, edit_text, set_edit_text, apply_edit) lets the assault suite drive the same path a human does.

Two presentations. Floating: a centered sheet with the window's new modal chrome (header band drags it, corner grip resizes it, danger-red pearl closes it). Docked: Larry recognised the shape - EiffelStudio's debugger pane - so a pinned right drawer hosts the studio while the page underneath STAYS LIVE: clicks, wheel, hover, drops and pebbles outside the panel route to the app (the window's target_at rule).

Pick-and-drop re-rooting closes the cycle: with dev mode on, middle-click lifts ANY control as its own pebble; drop it on the mesh and the graph rebuilds around it - new crown, depths re-zeroed, the pane following via on_select. Works across the dock boundary: pick from the live page, drop into the drawer.

Release absence is measured, not promised: all three classes live only in the devkit override cluster; the release-shaped sw_7guis binary contains zero occurrences of their names in any encoding.

Opening it (dev builds)

-- Dev menu > "Dev Studio - floating sheet"
window.show_sheet (create {SW_DEV_STUDIO}.make_over (rw, 3), 860.0)

-- Dev menu > "Dev Studio - docked right (page stays live)"
window.show_drawer (create {SW_DEV_STUDIO}.make_over (rw, 3), 520.0, True)

-- from any dev-mode reveal popover: the "Mesh this subtree" button
-- re-roots the studio at the control you right-clicked.

-- pick-and-drop: dev mode ON, middle-click a control, drop on the mesh.

Known limits

  • Physics never fully sleeps (damping 0.82 + gravity) - nodes drift a pixel or two; drag pins a node (warning ring) when you need stillness.
  • The dossier is reflection over ATTRIBUTES - computed queries need dev_note.
  • Live edit covers SW_TEXT_BOX and SW_LABEL set_text today; the general property editor is future work.

Bugs & gotchas

  • Larry's law: the instrument never inspects the instrument - dev chrome (mesh, studio, inspector columns) wears no hover chip, offers no reveal, and cannot be lifted by dev-mode middle-click (DEV_LENS.observes gates all three).
  • With a docked studio pinned, right-clicking a live-page control aims the dock's pane (no popover - it would replace the drawer). With a floating sheet up, the lens stays quiet; use node clicks and the node menu inside.
  • In the dock, an outside click no longer dismisses (that is the point) - close via the pin (unpin, then click away) or Escape with nothing focused.
  • Depth counts from the mesh's root, not the window's: a re-rooted mesh shows frontier badges at its OWN depth limit.

Extension plans & possibilities

  • Mutation flash: pulse nodes whose reflected fields changed since the last tick.
  • Event-stream pane; computed-vs-authored layout pane; focus-order overlay.
  • General property editing (is_enabled, is_muted, grow) through public setters.
