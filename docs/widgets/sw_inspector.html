Description

This page describes a planned control - nothing here ships yet. It exists so the design is public while it waits for its dependencies (the popover/overlay primitives later in Wave 3).

SW_INSPECTOR is the dev-mode lens over a running face. With dev mode on, right-clicking any widget opens a reveal overlay instead of (or stacked above) its normal context menu, showing: its class (free at runtime via Eiffel's generating_type), bounds, grow/min/max hints, state flags, and the theme tokens in force. The engine is Eiffel's own reflection - REFLECTOR / TYPE: field_count, field_name, field (i) - so any widget's attributes and live values enumerate generically, with zero per-class authoring. An opt-in dev_note on SW_WIDGET carries only what reflection cannot know: intent, provenance, wiring rationale.

The mesh view draws the widget graph as a force-directed network - springs on parent/child and agent edges, charge repulsion between nodes, a few dozen relaxation ticks on the heartbeat - the same physics family as EiffelStudio's Diagram Tool, which is the precedent that inspired it.

Two gates. Compile-time: every inspector hook lives inside debug ("dev_mode") instructions, stripped unless the ECF target sets <debug name="dev_mode" enabled="true"/> - production binaries carry neither the machinery nor the menu item, the same axis as Design by Contract itself (present in dev/fat builds, absent from lean releases, enforced by the compiler). Run-time: inside a dev build, a top-menu Dev Mode toggle - itself inside the debug block - opens control-level right-click reveals and the mesh.

Browser-inspector mining (Larry, 2026-08-22): the DevTools notions translate almost one-to-one, and three go further here. Element-pick mode (crosshair hover outlines the widget + a chip naming class and bounds - the window already tracks hover); the box-model overlay becomes a LAYOUT overlay (bounds, container padding/gap, grow/min/max annotations); the DOM tree panel is literally SW_TREE [SW_WIDGET] with bidirectional highlight - shipped machinery; the styles pane becomes the S03 appearance model NARRATED (kind + state, which tokens won, why); live CSS editing becomes token tweaking against the running theme - a theme-design tool falling out of the inspector; the event-listeners pane becomes the agent-wiring pane. Beyond the browsers: a CONTRACTS pane showing the live invariants guarding the selected widget, direct object identity (references, not selectors), and the REFLECTOR attribute dump as a props pane for free.

An AI-assist narrator rides later: once structure, state and wiring enumerate, answering 'why does this button look like this?' (which token, which state, which contract) is a small step - and one no desktop toolkit has shipped.

Source: src/sw_inspector.e · since planned - Wave 3 tail; design pinned in specs/S02, 2026-08-22. Live in the showroom: demo/sw_demo.e.

Bugs & gotchas

  • When it lands: reflection reads attributes, not computed queries - derived state (like is_hiding) will need the dev_note channel or explicit surfacing.
