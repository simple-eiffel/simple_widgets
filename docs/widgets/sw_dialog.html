Description

SW_DIALOG is the message-box replacement: a kind stripe (Kind_info, Kind_success, Kind_warning, Kind_danger), a title, a word-wrapped message, and buttons added with add_button (label, primary, action). The window presents it above a dimmed backdrop (show_dialog); while open it owns all input; Escape or any button closes it, then the button's agent runs.

For modal forms - anything richer than title/message/buttons - use the sheet layer instead (window.show_sheet hosts any widget tree; SW_FILE_DIALOG is the reference rider).

Source: src/sw_dialog.e · since Wave 1 (2026-08-21). Live in the showroom: demo/sw_demo.e.

A danger confirm

create d.make ({SW_DIALOG}.Kind_danger, class="string">"Delete 3 items?",
    class="string">"This cannot be undone. The items will be removed from the library.")
d.add_button (class="string">"Cancel", False, Void)
d.add_button (class="string">"Delete", True, agent do_delete)
window.show_dialog (d)

Known limits

  • Title/message/buttons only - no embedded widgets (that is the sheet layer's job).
  • No default/cancel button semantics for Enter/Escape mapping to specific buttons (Escape simply closes).

Bugs & gotchas

  • Button agents run after the dialog closes; opening the next dialog from an agent is safe and sequential.
  • A Void action is the idiomatic Cancel - close and do nothing.

Extension plans & possibilities

  • Do-not-ask-again check row (the one embellishment worth having).
  • Enter activates the primary once focus traversal lands.
