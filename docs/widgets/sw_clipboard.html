Description

SW_CLIPBOARD is a small service class (create it anywhere, no window needed): set_text, text, has_text. Full Unicode both ways - astral code points are split to UTF-16 surrogate pairs on write and re-paired on read (R8), so an emoji survives the round trip as one code point.

Both directions retry briefly: clipboard-history managers (Win+V and friends) open the clipboard right after every change, so back-to-back OpenClipboard calls lose races. Writes retry until accepted; reads retry when the format probe says text exists but the read came back empty - the race's exact signature. The assault suite flushed this out; five consecutive clean runs sealed it.

Source: src/sw_clipboard.e · since Wave 1 (2026-08-21); race hardening Wave 2. Live in the showroom: demo/sw_demo.e.

Round trip

local
    clip: SW_CLIPBOARD
do
    create clip
    clip.set_text (class="string">"copied by simple_widgets")
    if clip.has_text then
        print (clip.text)
    end
end

Known limits

  • Text only - no images, files or custom formats yet.
  • Reads cap at 128k characters (a paste larger than that truncates).

Bugs & gotchas

  • Masked text boxes never write here - copy denial is enforced in SW_TEXT_BOX, not in the clipboard.
  • The clipboard is global mutable state shared with every other app; test suites doing rapid ops should assert on sentinels, not on emptiness.

Extension plans & possibilities

  • Image (PNG) transfer - pairs naturally with SW_IMAGE.
  • File-drop list format for the dropzone widget (Wave 3).
  • Clipboard-change notification for paste-aware UI enablement.
