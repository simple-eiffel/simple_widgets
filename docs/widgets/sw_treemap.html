Description

Labelled items tiled into the plot by recursive bisection: the range splits where cumulative value crosses half, the rectangle splits in the same proportion, and the split axis alternates per level. The layout is deterministic pure math with an EXACT property the assault asserts to a millionth: every item's area fraction equals its value fraction, and the tiles sum to the plot with no gaps and no overlaps (item_at answers uniquely at every tile centre).

Tiles wear the pie's eight-step palette; labels draw only when they fit (measured, not clipped); hover outlines the tile and names label, value and share. refresh_layout is public - draw calls it every frame, the assaults call it headless.

Source: src/sw_treemap.e · since Wave 4, Densities (2026-08-22). Live in the showroom: demo/sw_demo.e.

The library as areas

create tm.make
tm.add_item (class="string">"Controls", 26.0)
tm.add_item (class="string">"Wave 3", 25.0)
tm.add_item (class="string">"Charts", 11.0)
page.put (tm.with_title (class="string">"the library as areas"))

tm.refresh_layout       -- then layout [i] holds each tile
tm.item_at (px, py)     -- which tile is under a point
tm.percent_of (2)       -- shares, summing to 100

Known limits

  • Slice-and-dice can go slivery on long tails - SQUARIFIED layout is the stated future (better aspect ratios, same public surface).
  • Single level - no nested hierarchies yet.

Bugs & gotchas

  • add_item requires value > 0: a zero-area tile is a lie about existence.
  • Add order shapes the tiling - group big items first for calmer layouts.

Extension plans & possibilities

  • Squarified layout; nested hierarchies (drill on click); value labels inside tiles.
