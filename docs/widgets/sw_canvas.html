Description

SW_CANVAS is the custom-drawing escape valve that keeps R2 intact: the host supplies an on_paint agent receiving an SW_PAINTER (never a raw context) plus the canvas rectangle, clipped automatically. Pointer traffic arrives as agents too - on_press and on_sweep in canvas-relative coordinates - and a menu_provider builds the right-click menu per point, riding the standard context-menu machinery.

Hover is live: wants_hover_point is on, so the paint agent can read hover_px/hover_py off the canvas for pointer-following effects. 7GUIs' Circle Drawer runs entirely on this widget - circles, nearest-hit fill, the adjust menu - with its model and undo/redo wholly app-side, as the task intends.

Source: src/sw_canvas.e · since Wave 3 / 7GUIs (2026-08-22). Live in the showroom: demo/sw_demo.e.

Circle Drawer's wiring (abridged)

create canvas.make (260.0)
canvas.set_on_paint (agent paint_circles)
canvas.set_on_press (agent on_canvas_press)
canvas.set_menu_provider (agent circle_menu)

paint_circles (a_p: SW_PAINTER; a_x, a_y, a_w, a_h: REAL_64)
    do
        across model.circles as c loop
            a_p.set_color (a_p.theme.ink)
            a_p.circle_stroke (a_x + c.cx, a_y + c.cy, c.radius)
        end
    end

Known limits

  • Fixed preferred height from creation (no aspect or grow-driven height yet).
  • No offscreen retained layer: the paint agent runs every frame - keep it light.
  • No key events routed (canvases are pointer surfaces today; focus work pending).

Bugs & gotchas

  • Paint in the given coordinates (a_x/a_y offsets), never absolute widget fields - the same rule as list row renderers.
  • The paint agent runs on the heartbeat too (4/s), so ambient animation is free - and so is accidental cost if the agent allocates.

Extension plans & possibilities

  • Retained-layer mode (paint once to a surface, blit until invalidated).
  • Key input routing when focus traversal lands.
  • Wheel and pinch agents for zoomable canvases (charts, Wave 4, will want them).
