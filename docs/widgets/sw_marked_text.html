Description

Seven classes, four concerns kept apart:

  • SW_MARK - what a highlight looks like: one of twelve hues through any combination of a wash behind the text, 0-3 box rules around it, 0-2 outlines traced around the glyphs, the glyphs coloured in the hue's ink, bold, italic. A value with a short code that round-trips through any store.
  • SW_MARK_PALETTE - the twelve hues as an ink and a wash per theme, held by contract: every wash reads under the theme's ink at 4.5:1, every ink reads on the surface at 3:1, on light and dark alike.
  • SW_MARK_LEGEND - what a highlight means: the application's reasons ("pronounce", "slow", "stale"), each with a look, a label and an optional one- or two-character badge. Re-theme a reason and every span carrying it changes at the next paint.
  • SW_MARK_SPAN and SW_MARKED_TEXT - the data behind the text: spans by id with a reason, an optional explicit look and an annotation; add, remove, restyle, re-reason, resize; and the arithmetic that keeps them honest as the text is edited (insert inside grows, at the start shifts, at the end does not grow; delete across trims; a collapsed span is dropped). A line-per-span codec for any store.
  • SW_TEXT_GEOMETRY - where every character paints on either engine, lifted out of the text box so a highlight, a caret and a hit-test read one object.
  • SW_MARK_PAINTER - washes under the text, then the effects and boxes over it, with a size policy: below one pixel size the glyph effects and badges are dropped, below another only the wash remains.
  • SW_MARK_LEGEND_VIEW - the legend drawn as a key with live swatches; a click hands the reason back.

SW_TEXT_BOX carries a marks and a legend and tells the marks about every edit, undo and redo included; SW_PARAGRAPH_LIST keeps one marked text per paragraph and hands the same object to its in-place editor.

Source: src/sw_mark*.e, src/sw_marked_text.e, src/sw_text_geometry.e · since 0.8.0 (2026-09-06), built for simple_narrate's speaking functions.

A palette of speaking functions

create legend.make
create m.make ({SW_MARK}.Hue_red)
legend.define ("pronounce", m.with_outline (1), "Say it this way")
legend.set_badge ("pronounce", "P")
create m.make ({SW_MARK}.Hue_teal)
legend.define ("slow", m.with_wash.italic, "Slow down")
box.set_legend (legend)
-- the user selects "qodesh" and picks "pronounce" from the legend view:
id := box.marks.mark_range (box.sel_anchor.min (box.caret), box.sel_anchor.max (box.caret), "pronounce")
box.marks.span (id).set_annotation ("koh-DESH")
-- later: box.marks.remove (id) / restyle (id, other) / rereason (id, "slow")
session.put_marks (block_id, box.marks.code)   -- any store

Known limits

  • Text outlines, bold and italic are approximations - offset passes and a shear - because the substrate strokes no glyph paths and the shaping facade shapes regular upright only. They never change a glyph's advance, which is the point.
  • A span is a flat range; nested structure is the application's to model with reasons.
  • The size floors are pixel sizes, not points; the painter reads the theme's body size times its scale.

Bugs & gotchas

  • set_text on a text box clears its marks; a host that wants them to outlive a text swap keeps its own object through set_marks.
  • A reason the legend does not know paints nothing; unresolved names such reasons so the application can notice.
  • Typing at the very end of a highlighted word does not extend the highlight; typing inside it does.

Extension plans & possibilities

  • A span-aware context menu on the text box (remove, change reason); hover tooltips reading the annotation; true glyph-path outlines if the substrate gains them.
