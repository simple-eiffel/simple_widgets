Description

SW_TREE applies the data grid's philosophy to hierarchy: your node objects stay yours. Wire three agents - set_roots, set_children (a FUNCTION over G, called lazily: roots are probed for their disclosure triangles, but a collapsed node's grandchildren are never touched - the assault suite counts the probes), and set_label - and the tree renders disclosure triangles, depth indentation, hover bands and a scrollbar over a virtualized flattening of whatever is open.

Expansion is tracked by object identity, and so is selection: fold the subtree containing the selected node and it stays selected - reopen and it is found again, the same object. Clicks on the triangle toggle; clicks on the row select (on_select (G)); double-click toggles parents and activates leaves (on_activate (G)). Arrows navigate; left collapses, right expands - the desktop grammar.

Source: src/sw_tree.e · since Wave 3 (2026-08-22). Live in the showroom: demo/sw_demo.e.

Known limits

  • Uniform row height; labels only - the drawn-glyph set landed 2026-08-23; node-icon adoption is queued (sweep 4+).
  • Single selection; no checkboxes/tri-state yet (queued with SW_CHECK_BOX's).
  • The flatten rebuild walks open subtrees each toggle - fine at desktop scale; incremental flattening is an S04 item for huge lazy trees.

Bugs & gotchas

  • Identity means REFERENCE identity: rebuild your node objects and the tree's expansion memory no longer matches them. Keep node objects stable across refreshes.
  • The children agent runs for triangle probing of every VISIBLE row - keep it cheap (return a stored list; do expensive fetching on first expansion yourself).

Extension plans & possibilities

  • Node icons; per-node checkboxes with tri-state cascade.
  • Incremental flattening for very large lazy trees.
  • SW_TREE_TABLE (Wave 5): this engine married to SW_DATA_GRID columns.
  • The SW_INSPECTOR's widget-tree panel is exactly SW_TREE [SW_WIDGET].
