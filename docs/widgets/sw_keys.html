Description

SW_KEYS answers modifier questions at the moment of asking - today just shift_down, read straight from the physical keyboard state. SW_TEXT_BOX uses it for Shift+Click selection extension. It exists so widgets never talk to Win32 directly (R2's spirit applied to input).

Source: src/sw_keys.e · since Wave 1 (2026-08-21). Live in the showroom: demo/sw_demo.e.

Shift-aware click handling

handle_click (a_px, a_py: REAL_64): BOOLEAN
    local
        keys: SW_KEYS
    do
        create keys
        caret := offset_at (a_px, a_py)
        if not keys.shift_down then
            sel_anchor := caret        -- plain click moves the anchor
        end                            -- Shift+Click extends instead
        Result := True
    end

Known limits

  • Shift only - Ctrl and Alt queries are trivial additions awaiting a consumer.

Bugs & gotchas

  • It reads the PHYSICAL keyboard - synthetic message-based tests cannot fake it, and a human holding Shift during automated runs changes behaviour. The test bench learned this the fun way.

Extension plans & possibilities

  • Ctrl/Alt/Win queries; a snapshot record for gesture recognizers.
  • A keymap/accelerator service registering app-wide shortcuts (feeding menu hints).
